# 2026-11-06 Google Play 실기기 구매 검증

**Google Play 설치본 버전 5에서 해달·광고 제거의 테스트 구매와 구매 복원은 동작했지만, 취소·거절 후 버튼이 계속 비활성 상태로 남는 문제를 재현했습니다.** 현재 소스 코드의 구매 자동 테스트 37개는 통과하지만, 이번 실기기 결과는 Play에서 배포 중인 버전 5에 대한 결과입니다.

## 환경과 데이터 보존

- 기기: Galaxy S23, SM-S911B. USB 연결 및 USB 디버깅 승인 완료.
- 앱: `dev.jaewook.deskmate`, Google Play 설치본. 이날 Play 업데이트로 버전 코드 **3 → 5** 전환.
- 앱 삭제·데이터 초기화는 하지 않았습니다. 진행 중 집중 세션이 없는 상태(`25:00`, 시작 버튼)에서 검증했으며 저장된 목표가 유지된 것을 확인했습니다.
- 해달(`friend_otter`)의 표시 가격: **₩1,200**.
- 광고 제거(`remove_ads`)의 표시 가격: **₩2,000**.
- Google Play 구매창에서 **항상 승인 테스트 카드와 실제 청구가 없다는 안내**를 확인했습니다. 아래 거절 검증도 테스트 결제 수단을 사용했습니다.
- 구매 소스 코드 수정, 새 빌드 생성, Play 배포는 이번 실기기 검증에서 수행하지 않았습니다.
- 최종 휴대폰 상태는 **Play 버전 5, 해달·광고 제거 테스트 구매 보유**입니다. 새 소스가 포함된 빌드를 업로드하거나 설치하지 않았습니다.

## 현재 코드의 수정과 구분

현재 코드의 커밋 `6ece389`에는 상품 ID가 비어 있는 취소·오류 이벤트를 받으면 활성 구매 요청을 끝내는 처리가 있습니다. Android 구매 플러그인은 구매 목록이 없는 취소·오류를 빈 상품 ID로 전달합니다. 수정 이전 구현은 상품 ID로 대기 요청을 찾았으므로, 이런 이벤트에서 실제 상품의 대기 요청이 끝나지 않아 화면의 구매 중 상태가 유지될 수 있었습니다.

실기기 증상은 이 수정 이전 동작과 일치합니다. 다만 **버전 5 바이너리의 소스 커밋을 직접 대조하지 않았으므로 원인 대응은 추정**입니다. 현재 수정 코드가 포함된 빌드를 설치하여 취소·거절 후 재시도가 가능한지 다시 확인해야 합니다.

- 수정: [구매 서비스의 빈 상품 ID 처리](../../../lib/purchases.dart)
- 서비스 회귀 테스트: [play_purchases_test.dart](../../../test/play_purchases_test.dart)의 `Android PurchaseStatus.canceled without a product ID ends the active request`, `Android PurchaseStatus.error without a product ID ends the active request`
- 화면 회귀 테스트: [purchases_test.dart](../../../test/purchases_test.dart)의 `a cancelled friend purchase can be retried`, `a cancelled bundle purchase can be retried`
- 이날 현재 소스 코드에서 구매 서비스 22개와 구매 화면·보유 판단 15개, **총 37개 통과**. 함께 실행한 Play 스토어 링크 테스트 6개를 포함하면 43개 통과.

상품 등록과 이전 배포 준비 내용은 [구매 검증 문서](../purchase-testing.md)에 날짜별로 보존했습니다. 11월 5일 미등록이었던 상품의 현재 상태나 실제 주문 승인 여부를 이번 화면 확인만으로 확정하지 않습니다.
