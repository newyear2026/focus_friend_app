# 현재 휴식 모션 비교: 랫서팬더 · 다람쥐 · 사막여우

결론: 세 캐릭터 모두 2D 그림 기반이지만 현재 재생 방식은 다릅니다. 새 두 캐릭터는 부족한 중간 자세를 혼합·변형으로 연결하고 있어, 랫서팬더의 연결 원화 재생보다 윤곽과 움직임의 일관성이 부족합니다. 기능 테스트 통과를 같은 수준의 시각적 자연스러움으로 해석해서는 안 됩니다.

[현재 속도로 움직이는 비교 화면](http://127.0.0.1:8127/docs/design/rest-motion-comparison-v1/). ‘차 마시기 시작점 맞추기’는 각각 3.333초와 6.28초로 재생 위치만 옮기며 재생 속도는 모두 1배입니다.

## 범위와 새 캡처

현재 Flutter 앱의 **휴식**을 비교했습니다. `tool/capture_rest_motion_comparison_test.dart`로 세 친구를 같은 390×844dp, DPR 2, 저녁 18시, 5분 휴식, 해금 소품 없는 MemoryStore 상태에서 새로 캡처했습니다. 설치 앱의 기록·친구 선택·세션은 읽거나 변경하지 않았습니다. 이 비교에서 앱의 실행 코드나 원화를 수정하지 않았습니다.

영상은 실제 FocusFriendApp 위젯을 캡처한 것입니다. 전체 앱 출력은 780×1688px이며, 세 영상 모두 같은 방 좌표 x=100..800, y=600..1260을 490×462px로 표시했습니다. 캐릭터만 따로 크기를 맞추지 않았으므로 앱에서 실제로 보이는 크기 차이도 유지됩니다. 랫서팬더는 10초·120프레임, 다람쥐와 사막여우는 각각 22초·264프레임, 출력은 모두 12fps입니다. 새 두 캐릭터의 앱 갱신은 약 30fps이므로 영상이 앱의 모든 갱신 프레임을 포함하지는 않습니다.

14장이나 6개라는 수치만으로 품질을 결정할 수는 없습니다. 이 경우 랫서팬더에는 동작 사이를 이어주는 별도 그림이 있고, 새 두 친구는 연속해서 그리지 못한 변화를 영상 합성으로 보완하는 차이가 큽니다. 랫서팬더 역시 한 자세씩 교체하는 셀 애니메이션이며, 자동으로 모든 순간을 계산하는 관절 애니메이션은 아닙니다.

## 1. 기본 자세·대기 — 정지 자세는 좋음, 새 친구의 생동감 보완 필요

![기본 자세 비교](01-start-browser.png)

세 캐릭터 모두 방과 책이 안정적이고 한 잔을 두 손으로 잡는 의미가 잘 보입니다. 새 두 친구는 반복 끝 5.92초와 다음 반복 처음 6.28초가 같은 0번 자세이므로 **약 12.2초 동안 같은 그림**이 이어집니다. 별도 눈 깜빡임 원화 1번은 현재 시간표에서 사용하지 않습니다. 잔잔함을 주지만 완전히 멈춘 그림처럼 느껴질 수 있습니다. 랫서팬더는 대기 중 별도 눈 깜빡임이 있습니다.

근거: 첫 캡처, 전체 영상, `lib/friend_motion_clock.dart`의 `windowTeaFrames`, `windowTeaSegmentsMs`; 랫서팬더는 `lib/rest_animation.dart` 시간표.

## 2. 잔 들기 — 랫서팬더 양호, 새 두 친구 P2 개선 필요

![차 들기 시작점 비교](02-lifting-browser.png)

시작점을 맞춰도 다람쥐의 컵·앞팔은 일부 중간 프레임에서 두 윤곽이 함께 보입니다. 사막여우는 잔을 얼굴 쪽으로 가져갈 때 수평 이동과 얼굴 자세 변화가 상대적으로 커집니다. 얼굴은 인접 원화 중 하나로 교체하고 몸 쪽은 혼합하므로 표정과 팔이 같은 방식으로 이어지지 않습니다.

코드상 각 원화 구간마다 smoothstep을 새로 적용합니다. 이 함수는 구간 시작·끝에서 속도가 0이 되어, 한 번 잔을 드는 동작 안에서도 감속과 출발을 반복합니다. 이는 멈칫하는 인상을 줄 수 있는 원인으로 판단됩니다. 화면 갱신 빈도를 높이는 것만으로 원화의 윤곽 차이나 이 속도 구조가 해결되지는 않습니다.

새 캡처 영상의 동작 전체를 0.5초 간격으로 추출한 비교:

- [랫서팬더 0~10초](redpanda-action-contact.jpg)
- [다람쥐 6.28~16.28초](squirrel-action-contact.jpg)
- [사막여우 6.28~16.28초](fennec-action-contact.jpg)

랫서팬더의 중간 원화 재생은 `lib/rest_companion.dart`, 새 두 친구의 혼합·위치 변형·얼굴 선택은 `lib/friend_motion_scene.dart`의 `_windowTea`입니다. 사막여우의 컵 기준점은 5→6번에서 x314→346으로 변하며, 앞 구간의 작은 이동보다 변화가 큽니다.

## 3. 한 모금·복귀 — 완성 자세는 양호, 새 친구의 중간 연결 보완 필요

![한 모금 자세 비교](03-sipping-browser.png)

한 모금 완성 자세 자체는 세 캐릭터 모두 잘 읽힙니다. 위 화면은 랫서팬더 5.25초, 새 두 친구 11.6초에서 정지한 실제 영상입니다. 새 두 친구는 기본 자세로 역순 복귀하며 이전에 혼합했던 윤곽 변화가 복귀에서도 나타납니다. 랫서팬더는 내리는 과정과 복귀에 대응하는 별도 원화·중간 그림을 순서대로 재생합니다.

## 추천 수정

1. 창밖을 향한 새 캐릭터의 얼굴·안경·몸 크기와 꼬리 기준을 고정하고, 잔을 들고 내리는 **연결된 중간 원화**를 먼저 보강합니다.
2. 랫서팬더처럼 완성된 연속 그림을 재생하는 것을 기본으로 삼고, 큰 형태 차이를 혼합·변형으로 가리는 비중을 줄입니다.
3. 잔을 드는 전체 동작이 한 번 가속·감속하도록 시간표를 맞춥니다. 22초의 여유 있는 전체 분위기는 유지할 수 있습니다. 대기에는 작고 짧은 눈 깜빡임을 별도 추가하는 편이 좋습니다.

‘몇 장이면 자동으로 자연스러워진다’고 보기는 어렵습니다. 같은 얼굴·몸 크기, 한 방향의 컵 이동 경로, 연결된 어깨·팔, 올리고 내리는 중간 자세가 먼저입니다.

## 접근성 및 검증 한계

이번 범위는 세 친구의 장식용 휴식 동작과 비교 플레이어입니다. 비교 플레이어의 함께 재생·일시정지·시작점 이동·한 모금 정지와 1배 속도, 미디어 오류 없음을 현재 브라우저에서 확인했습니다. 앱 코드에는 일시정지·동작 줄이기 처리가 있지만, 이번 비교에서 운영체제 보조기술이나 전체 접근성 준수를 평가하지 않았습니다. 12fps 영상과 정지 화면만으로 모든 30fps 합성 구간이나 기기별 성능을 단정할 수 없습니다.

캡처 테스트 1개 통과: `capture.log`. 원화 번호와 캡처 시계는 `capture-manifest.json`, 브라우저 구간 이동 결과는 `browser-verification.json`, 소스 파일 해시는 `source-evidence.json`에 있습니다. 기존에 만든 영상이나 스크린샷은 이번 비교의 근거로 재사용하지 않았습니다. 첫 일반 정적 서버에서 영상 구간 탐색이 동작하지 않아 해당 구간 캡처를 폐기하고, 바이트 범위를 지원하는 8127 서버에서 1~3단계를 다시 캡처했습니다.
