# 36장 캐릭터 프레임 — 앱 연결

## 구현

- 홈의 집중 시작으로 같은 방에서 재생한다. 필기 12장 → 생각하기 12장 → 필기 반복 → 페이지 넘기기 12장을 연결했다.
- 12fps 기준 112틱(약 9.33초): 필기 3초, 생각하기 2초, 필기 3초, 페이지 넘기기와 마지막 자세 유지 약 1.33초. 생각 중 두 자세를 길게 유지한다.
- 일시정지, 앱 백그라운드, 비활성 TickerMode, 동작 줄이기에서는 현재 위치를 보존하며 멈춘다. 재개하면 그 위치에서 이어진다.
- 집중 종료·완료·휴식에는 기본 자세로 돌아오고 새 집중은 처음부터 재생한다. 모션의 재생 시간은 집중 기록 저장과 분리되어 있다.
- 방의 시간대 전환 및 보상 소품은 기존 위젯을 사용한다. 캐릭터는 각 자세를 통째로 그리며 관절 변형이나 교차 페이드를 사용하지 않는다.

## 에셋

- 런타임: `assets/images/redpanda-study-animation.png`, RGBA 1448×3258, 4열×9행, 셀 362×362.
- 승인된 각 12장 시트의 배경과 책상 부분을 built-in Image Gen으로 제거했다. 투명 시트 3장을 기계적으로 세로 연결했으며, 연결 전후 셀 픽셀 일치를 확인했다.
- 생성 모드·참고 이미지·정확한 프롬프트: [asset-prompts.md](asset-prompts.md).

## 검증

- `flutter analyze`: 문제 없음.
- `flutter test`: 40개 통과. 반복 주기, 세 동작 전환, 생각 자세 유지, 일시정지·백그라운드·숨겨진 Ticker의 위치 보존과 재개, 종료·새 시작을 확인했다.
- `flutter test tool/render_study_motion.dart --dart-define=FRAME_STEP=6`: 통과. 실제 렌더러로 필기·생각·페이지 넘김의 책상 위치와 투명 배경을 눈으로 확인했다.
- `python3 tool/verify_study_animation.py`: Android 통합 테스트 통과. 별도 임시 소스 복사본과 `.verification` 패키지의 메모리 저장소로 검증했으며 일반 앱의 SQLite 기록을 사용하지 않았다.
- 홈의 네 시간대, 필기·생각·페이지 넘김, 다음 주기의 필기, 일시정지·재개, 완료·보상·휴식·홈 복귀의 화면 13개를 저장했다. `paused-a.png`와 `paused-b.png`는 2초 간격으로 픽셀이 동일하다.
- 실행 영상: [Android 녹화](native-animation.mp4), [앱 렌더러의 두 주기](room-animation.mp4). Android 테스트는 고정 시각의 메모리 타이머를 사용하므로 녹화의 숫자는 25:00으로 유지된다.
- 초기 검증은 공유 빌드 파일 충돌과 기존 에뮬레이터의 시스템 서비스 중단·응답 없음으로 실패했다. 빌드 경로를 분리하고 에뮬레이터를 데이터 삭제 없이 완전히 재시작한 후, 같은 동작 검증이 통과했다. `integration.log`는 성공한 최종 실행의 로그다.
- 검증한 소스와 현재 앱 소스의 일치, 일반 APK의 패키지 ID와 포함된 프레임 에셋의 일치를 확인했다. `adb install -r`로 개발 앱을 업데이트했으며 SQLite 상태 본문의 설치 전후 SHA-256이 동일하고 기존 기록 5개가 유지됐다. 결과는 [data-preservation.json](data-preservation.json)에 있다.

실행 환경: Flutter 3.41.4 / Dart 3.11.1, Android 에뮬레이터 Pixel 3. 실기기 성능 검증은 별도다.
