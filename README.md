# Deskmate

Android 우선 Flutter 앱. 로컬 프로젝트 이름은 `focus_friend_app`, Android 앱 ID는 `dev.jaewook.deskmate`, 설치 이름은 모든 언어에서 **Deskmate**입니다. 앱 ID는 Play에 올린 뒤 바꿀 수 없습니다. Kotlin 소스의 `namespace`/패키지(`dev.jaewook.prototype.focus_friend_app`)는 앱 ID와 별개인 내부 이름이라 그대로 둡니다.

## 실행

```sh
flutter pub get
flutter analyze
flutter test
python3 tool/verify_android.py --persistence
python3 tool/verify_android.py
flutter build apk --debug
flutter run -d emulator-5554
```

Android만 생성했습니다. Flutter 3.41.4 / Dart 3.11.1에서 검증합니다. 저장 통합 테스트는 `verification.db`만, 화면 통합 테스트는 메모리 저장소만 사용하며 일반 앱의 `focus.db`를 초기화하지 않습니다. 통합 테스트는 위 `tool/verify_android.py`로 실행합니다. 이 도구는 `.verification` 식별자를 가진 APK를 먼저 빌드한 뒤 같은 식별자로 테스트를 실행합니다. Flutter는 테스트 시작 전 기존 APK에서 종료 시 삭제할 패키지를 읽으므로, 일반 앱 APK가 남은 상태에서 통합 테스트를 직접 실행하지 마세요. 디버그 앱에만 이 테스트 저장소와 트랜잭션 실패 주입이 허용됩니다.

## 작은 범위

- 방 하나와 책상·화분/머그컵/조명의 고정 자리 3개. 홈은 선택한 시안 기반의 랫서팬더 캐릭터와 보상 에셋을 사용합니다. 집중·일시정지·완료·휴식도 같은 홈의 방에서 이어집니다. 별도 집중 화면으로 이동하지 않습니다.
- 홈은 나의 책상 → 방 일러스트 → 오늘의 집중 → 25/50분 선택 → 집중 시작 순서입니다. 랫서팬더 랜덤 선택은 시간을 고르기만 하며 자동 시작하지 않습니다. 집중 시작 시 오늘의 집중 수치가 타이머로 바뀌고 방의 위치는 유지됩니다. 집중 중 하단 메뉴는 같은 높이를 남겨 숨깁니다.
- 정상 집중 25/50분을 홈에서 고르고, 설정 탭에서 5/15분 집중과 1분 체험을 시작할 수 있습니다. 조명은 처음부터 기본 제공하며 기존 사용자에게도 즉시 표시합니다. 최초 정상 완료에 화분, 완료 시간 누적 60분에 머그컵을 받습니다. 후속 기준은 시제품용 값입니다.
- 일시정지, 재개, 중도 종료, 재실행 복구, 최근 100개 기록과 별도 평생 누적/해금 기록.
- 중도 종료 확인은 랫서팬더 원화가 있는 하단 패널에서 합니다. 선택한 시안처럼 겹친 책장 테두리, 청록 책갈피와 접힌 모서리를 적용했습니다. 큰 주황색 **계속하기**는 패널을 닫고, **종료하기**를 눌렀을 때만 종료합니다. 바깥 터치·아래로 밀기·뒤로 가기도 현재 세션을 유지합니다. 큰 글자에서는 패널을 스크롤할 수 있습니다. 비교 화면과 검증 결과는 `docs/design/session-stop/book-frame/`에 있습니다.
- 1분 체험과 5분 휴식은 별도 mode를 가진 세션입니다. 정상 기록/누적/해금에 영향을 주지 않습니다. 휴식과 다음 집중은 완료 화면에서 명시적으로 눌러야 시작합니다.
- 캐릭터 동작: 몰입형 홈은 책과 글씨를 고정하고 연결된 캐릭터 원화를 교체합니다. 필기 중 얼굴·몸통·꼬리를 기본 원화로 유지하고 연결된 팔과 연필 영역만 자세별 원화로 교체합니다. 작은 4초 왕복 필기를 36초 동안 이어간 뒤, 보강한 중간 자세를 거쳐 5.5초 동안 페이지를 넘깁니다. 전체 41.5초 주기이며 넘김의 시작과 끝에 동일한 필기 원화를 사용합니다. 종이를 놓을 때와 필기로 돌아올 때 같은 연결된 자세를 사용합니다. 일시정지·백그라운드에서는 그림·글씨·재생 위치를 보존하고 기기의 동작 줄이기 설정을 따릅니다. 타이머와 집중 기록 저장은 시각 동작과 분리합니다. 최신 원화·프롬프트·영상·검증 기록은 `docs/design/calm-connected-motion/`에 있습니다.
- 모든 친구의 현지 시간대: 아침 05:30–07:59, 낮 08:00–17:29, 저녁 17:30–19:59, 밤 20:00–05:29. 창밖과 방 조도가 2초 동안 전환되며, 대기 상태도 매분 확인하고 앱 복귀 시 갱신합니다. 다섯 친구 모두 필기·페이지 넘김·휴식 원화에 조명을 함께 전환합니다. 동작 줄이기에서는 즉시 전환합니다. 실제 Android 적용 화면·시안 비교·데이터 보존 검증은 [시간대별 배경 적용](docs/design/friend-time-of-day-implementation/README.md)에 있습니다. 위치 기반 일출·일몰 계산은 아닙니다.
- 자유 배치, Rive, 계정, 동기화, 재화, Firebase 없음. 광고는 아래 [광고 (AdMob)](#광고-admob), 결제는 [구매 (Google Play Billing)](#구매-google-play-billing) 참고.

## 저장과 완료 규칙

`SessionEngine`은 모든 변경을 직렬화하고 세션 ID와 상태를 검사합니다. Android `SnapshotDb`는 SQLite의 단일 트랜잭션에서 revision을 비교하고 전체 상태를 교체합니다. 현재 세션, 최근 기록, 일별 합계, 평생 완료 시간/횟수, 해금 시각, 목표와 사운드 설정, 화면 켜두기 설정이 함께 저장됩니다. UI는 저장 성공 후에만 상태를 반영합니다. 화면은 저장된 상태가 바뀔 때만 새로 만드는 읽기 전용 복사본 하나를 함께 읽으므로, 타이머가 도는 동안 상태 전체를 반복해서 복사하지 않습니다. 커밋 응답이 유실되거나 쓰기가 실패하면 다음 조작 전에 저장소를 다시 읽습니다.

실행 중에는 저장된 `endAt`, `remainingMs`, `actualMs`, `segmentAt`으로 현재 남은 시간/실제 진행 시간을 유도합니다. 시작·멈춤·재개·종료·완료 전환에 영구 저장하며 매 프레임 저장하지 않습니다. 일시정지는 `actualMs`와 잔여 시간을 확정하고 종료 시각을 비웁니다. `actualMs`는 백그라운드 시간을 포함하고 일시정지를 제외한 타이머 진행 시간이지 사용자 주의 집중을 측정한 값은 아닙니다.

완료는 실행 중인 같은 세션의 종료 시각에 도달했을 때만 인정합니다. 95% 규칙은 없습니다. 종료 시각 이후 Stop을 누르면 정상 완료가 우선합니다. 재실행 시 이미 종료 시각이 지난 세션은 한 번만 완료하고 완료 화면을 유지합니다. 중도 종료도 기록하지만 보상 누적에서는 제외합니다. 최근 기록을 잘라도 평생 누적/해금은 줄지 않습니다.

벽시계 기준이므로 사용자가 시스템 시각을 변경하면 완료 시각도 영향을 받습니다. 단순 역행은 음수 경과 시간으로 계산하지 않습니다. 설치 삭제나 OS 데이터 삭제까지 보존하는 백업 기능은 없습니다. 저장 오류/지원하지 않는 schema는 빈 기록으로 덮어쓰지 않고 복구 오류를 표시합니다.

## 알림은 타이머와 별도

Android 13 이상에서 `POST_NOTIFICATIONS`를 사용자가 **알림 켜기**로 요청합니다. 특별한 정확 알람 권한이나 절전 예외를 요청하지 않습니다. `AlarmManager.setAndAllowWhileIdle`의 부정확 알림이므로 절전/Doze/OS 정책에 따라 늦을 수 있습니다. 알림 수신기는 최신 세션 ID·상태·종료 시각을 확인하며 보상 저장을 하지 않습니다. 보상은 앱 실행/복귀 시 코어에서 확정합니다.

강제 종료(force-stop)와 기기 재부팅 뒤 알림 재예약은 보장하지 않습니다. 앱을 다시 열면 타이머 상태를 복구합니다. 재부팅 수신기와 정확한 완료 알람은 이 버전에 없습니다. 사운드의 mediaPlayback foreground service는 사용자가 소리를 켰을 때만 실행하며, 알림·집중 기록 저장과 분리됩니다. 알림 권한 거부 시에도 집중 저장과 복구는 가능합니다. 원격 동기화가 범위 밖이므로 이 새 앱의 OS 자동 백업도 끕니다.

참고: [Android 알람 지침](https://developer.android.com/develop/background-work/services/alarms), [알림 권한 지침](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [Flutter MethodChannel](https://api.flutter.dev/flutter/services/MethodChannel-class.html).

## 시각 참고와 원본 보호

초기 구현에서는 Library 참고 이미지를 HTTP 403 때문에 읽지 못해 `CustomPainter`로 간단한 방을 그렸습니다. 이후 사용자가 직접 첨부한 4화면 디자인의 **첫 번째 홈**을 기준으로 `lib/desk_home.dart`를 새로 구현했습니다. 기존 앱 런타임과 저장소를 재사용합니다. 현재 집중 흐름은 홈에 통합했으며 소품 화면에도 같은 랫서팬더를 표시합니다. 새 기록·사운드·목표 화면은 사용자가 선택한 각각의 시안을 따르되 현재 캐릭터에 맞췄습니다.

홈의 시간대별 방 4개, 랫서팬더 필기 포즈 시트와 소품 3개는 built-in Image Gen으로 제작한 개별 투명 PNG입니다. 현재 방과 소품은 캐릭터에 맞춰 짙은 윤곽선과 무광 질감의 2D 동화풍으로 통일했으며 `assets/images/immersive/`에서 사용합니다. 앱에 들어가는 이미지는 `pubspec.yaml`에 파일 단위로 등록합니다. 정확한 편집 프롬프트와 합성 검증은 `docs/design/unified-room-style/`에 보관합니다. 전체 목업을 화면으로 쓰지 않으며 제목, 수치, 선택, 버튼, 내비게이션은 실제 Flutter 위젯입니다. 초기 에셋의 생성 프롬프트는 `assets/images/*.prompt.txt`에 남겨 두었습니다. 참고 그림과 세부 일러스트가 완전히 동일하지는 않습니다. Pretendard v1.3.9 가변 글꼴과 OFL 라이선스를 `assets/fonts/`에 포함했습니다.

`오늘의 집중`과 달력은 기기 현지 완료일 기준의 일별 저장 합계를 사용합니다. 체험·휴식·중도 종료는 스탬프와 합계에서 제외합니다. 새 일별 합계는 상세 기록 100회 보관 제한과 별도로 유지합니다. 기존 데이터는 남아 있는 정상 완료 기록만 일별로 이관하므로, 업데이트 전에 이미 삭제된 오래된 상세 기록의 날짜별 합계는 복원할 수 없습니다. 평생 합계와 보상 저장 규칙은 유지합니다.

홈 디자인 비교와 실행 캡처는 `design-qa.md`, `docs/design/`를 참고하세요. 선택한 캐릭터 시안은 `docs/design/character-concepts/redpanda-writing-study.png`, 시간대 비교는 `docs/design/redpanda-study/`, 36장 프레임의 초기 앱 연결과 에셋 제작 기록은 `docs/design/app-cel-motion/`, 속도와 전체 흔들림을 수정한 최신 검증은 `docs/design/calm-study-motion/`에 있습니다. 실제 Android 동작은 `python3 tool/verify_study_animation.py`로 별도 검증용 패키지에서 확인합니다. 투명 프레임의 정확한 편집 프롬프트는 `docs/design/app-cel-motion/asset-prompts.md`에 보관합니다. 루틴 앱의 랫서팬더 원본은 읽기 전용 참고로 사용했습니다.

RandomFocus의 저장 코드를 복사하지 않았습니다. 종료 시각으로 복구하는 원칙만 참고했습니다. 기존 Firebase/광고 설정, 키, 사용자 데이터, 앱 식별자는 재사용하지 않았습니다. 로컬 Git만 초기화했으며 커밋·원격 연결·푸시·배포는 하지 않습니다.

세부 진단과 실행 검증은 `docs/`를 참고하세요.


## 기록 · 목표 · 집중 사운드

- **책상 / 기록 / 설정** 하단 메뉴. 기록에는 월 이동, 집중한 날의 스탬프, 선택 날짜의 합계·최근 세션 내역을 표시합니다.
- **설정 → 타이머 중 화면 켜두기**(기본 꺼짐)를 켜면 집중·체험·휴식 타이머가 진행되는 동안 `FLAG_KEEP_SCREEN_ON`으로 화면을 켜 둡니다. 일시정지·완료·종료 때 바로 풀고, 다른 앱으로 가면 Android가 자동으로 풉니다. 별도 권한은 없습니다.
- **설정 → 목표와 다짐**에서 이름·날짜·응원 문구·홈 표시 여부를 저장합니다. 홈 D-day를 눌러 같은 편집 화면으로 돌아갑니다. 날짜 차이는 달력 날짜로 계산하므로 일광 절약 시간의 23/25시간 날짜도 하루로 셉니다.
  앱 복귀나 타이머 변경 작업과 저장 요청이 겹치면 순서대로 기다려 저장합니다. 저장 중에는 진행 표시와 안내를 보여주고 뒤로 가기와 중복 입력을 막으며, 실제 저장이 성공한 뒤에만 편집 화면을 닫습니다. 실패하면 입력 내용을 유지하고 저장 버튼 위에 재시도 안내를 표시합니다.
- **책상 상단 스피커 / 설정 → 소리 기본 설정**에서 빗소리·숲·장작을 미리 듣고 선택·음량·음소거·자동 종료를 저장합니다. 취소하면 이전 설정과 재생 상태로 돌아갑니다.
- 음원은 APK에 포함되어 오프라인 재생합니다. 출처의 CC0 표기를 확인한 파일과 원문 증거는 `docs/audio-sources/README.md`, `assets/audio/LICENSE.txt`에 있습니다. 앱 설정에서도 출처를 볼 수 있습니다.
- Android MediaPlayer와 mediaPlayback foreground service로 백그라운드 재생합니다. 집중 종료 시 800ms 동안 음량이 줄고 꺼집니다(옵션). 일시정지·휴식·중도 종료·알림의 정지 버튼·오디오 포커스 상실·이어폰 분리 시 멈춥니다. OS 강제 종료나 앱 작업 제거 뒤 자동 재생하지 않습니다.
- 별도 계정·외부 음악 스트리밍·마이크 권한은 사용하지 않습니다. 백그라운드 동작은 Android 16 에뮬레이터에서 검증했고 제조사별 실기기 절전 정책은 별도 확인이 필요합니다.

새 기능 검증: `python3 tool/verify_features.py`. 일반 개발 앱과 분리된 `.verification` 패키지로 UI, 실제 SQLite 저장, 음원 3종, 백그라운드 재생 및 종료를 확인합니다. 비교 이미지와 결과는 `docs/design/features/`에 저장합니다.

## 몰입형 2D 책상 화면

사용자가 공유한 황혼의 랫서팬더 책상 시안을 기준으로 홈을 전체 화면 일러스트로 바꿨습니다. 시간대별 방 4장, 기존 필기·휴식 캐릭터, 해금 소품, 실제 타이머·기록·설정을 같은 장면 위에 배치했습니다. 버튼과 숫자는 Flutter 위젯이어서 집중 흐름과 접근성을 유지합니다. 소품은 원래의 해금 상태에 따라 나타나고, 기존 집중 기록과 목표는 그대로 표시됩니다.

시안 비교, 작은 화면·큰 글자 캡처, 실제 Android 설치 화면, 데이터 보존 결과는 `docs/design/immersive-room/`에 있습니다. 홈·기록·설정·목표·소리·집중·일시정지·완료·휴식 장면은 `flutter test --no-pub tool/capture_immersive_preview_test.dart`로 다시 캡처할 수 있습니다.

최신 [전체 캐릭터 모션 모아보기와 통합 검증](docs/design/all-character-motions-v10/README.md)은 다람쥐·사막여우에도 필기·페이지 넘김을 추가한 결과입니다. 다섯 친구 모두 집중과 휴식이 움직이며, 전체 주기를 1배속으로 기록했습니다. 두 친구의 집중은 필기 36초와 페이지 넘김 4.5초를 연결한 40.5초 주기입니다. [새 집중 원화와 생성 프롬프트](docs/design/squirrel-fennec-study-v1/README.md)에서 제작 자료를 확인할 수 있습니다.

후속 [필기·페이지 넘김 연결 검토](docs/design/study-continuity-audit-v1/README.md)에서는 주기 경계는 연결되지만 사막여우 필기 방향과 두 친구의 종이 들기·내려놓기 원화에 보강이 필요한 점을 확인했습니다. 재생 시계·고정 영역 테스트 통과와 중간 자세의 자연스러움은 구분합니다. 현재 앱 원화는 이 검토에서 변경하지 않았습니다.

2026-10-24 [추가 모션 품질 검토](docs/design/motion-quality-audit-v2/README.md)는 이후 페이지 순서·책상 연필·휴식 속도 수정까지 반영한 현재 코드의 새 캡처입니다. 첫 휴식 원화 로딩 중 시간대가 다른 기본 그림이 표시되는 문제를 재현했고, 글씨 누적·친구 미리보기의 모드 선택·펭귄 작화 보강을 다음 개선점으로 정리했습니다. 현재 10종 영상은 `docs/design/motion-quality-audit-v2/motions.html`에서 볼 수 있습니다.

## 광고 (AdMob)

`google_mobile_ads`와 Google UMP 동의를 `lib/ads.dart`에서 시작합니다. 앱 첫 화면이 그려진 뒤 동의 정보를 갱신하고, 필요한 지역(EEA·영국·스위스 등)에서 AdMob에 게시한 동의 메시지를 띄운 다음, 광고 요청이 허용될 때만 SDK를 초기화합니다. 동의 실패나 오프라인이어도 앱은 그대로 동작합니다. 필요한 지역에서는 **설정 → 광고 개인정보 설정**이 나타나 동의를 다시 고를 수 있습니다. 일반 위젯 테스트는 `FocusFriendApp`에 `ads`를 넘기지 않으므로 SDK를 부르지 않습니다. 기록 하단과 설정의 네이티브 광고는 이미지·영상용 `MediaView`가 포함된 Google medium 템플릿을 350 dp 높이로 표시합니다. 보상형 광고는 아직 연결하지 않았습니다.

실제 ID는 git에 넣지 않는 `admob.json`에 둡니다. `admob.example.json`을 복사해 AdMob 앱 ID와 광고 단위 ID를 채우세요. 이 파일 없이 빌드하면 Google 샘플 앱 ID와 테스트 광고 단위를 씁니다. 실제 광고 단위는 릴리스 빌드에서만 쓰이고, 디버그·프로필 빌드는 파일이 있어도 테스트 광고를 받습니다.

```sh
flutter build appbundle --release --dart-define-from-file=admob.json
```

유럽 동의 흐름은 디버그 빌드에 `--dart-define=ADMOB_DEBUG_EEA=true`를 주면 에뮬레이터에서 확인할 수 있습니다(릴리스 빌드는 무시). 캡처는 `docs/design/admob-consent-v1/`에 있습니다.

비공개 테스트 빌드는 `admob.json` 없이 올려 테스트 광고로 흐름만 확인하는 것을 권장합니다. 실제 광고를 직접 누르면 AdMob 계정이 제한될 수 있습니다. SDK가 `INTERNET`, `ACCESS_NETWORK_STATE`, `AD_ID` 권한을 병합하므로 Play Console의 광고 ID 신고와 데이터 보안 양식을 함께 갱신해야 합니다. 개인정보처리방침(`privacy/index.html`)에 AdMob 내용을 반영했습니다.

## 구매 (Google Play Billing)

`in_app_purchase`로 한 번 사면 계속 쓰는(비소모성) 상품 5개를 팝니다. 계정·서버 없이 Google Play가 영수증을 보관하고, 앱이 실행·복귀할 때마다 `queryPastPurchases`로 다시 확인합니다. 새 구매는 바로 승인(acknowledge)해서 Play가 3일 뒤 자동 환불하지 않게 합니다. 코드는 `lib/purchases.dart`(상품·보유 판단·Play 연결), `lib/purchase_sheet.dart`(묶음 시트·잠금 표시)에 있습니다. 결정 근거와 시안은 `docs/design/bm-mockup/bm-v5.png`, 실제 화면 캡처는 `docs/design/purchases-v1/`에 있습니다.

| 상품 ID | 내용 | 한국 가격 |
| --- | --- | --- |
| `friend_otter` | 해달 | ₩1,500 |
| `friend_squirrel` | 다람쥐 | ₩1,500 |
| `friend_fennec` | 사막여우 | ₩1,500 |
| `remove_ads` | 기록·설정의 광고 제거 | ₩1,000 |
| `all_friends` | 위 친구 3명 + 광고 제거. 앞으로 나올 친구는 포함하지 않음 | ₩3,500 |

- 랫서팬더와 펭귄은 무료입니다. 가격은 앱에 적지 않고 Play가 알려준 현지 가격을 그대로 보여줍니다. 국가별 가격(예: 멕시코 MX$15 / MX$10 / MX$35)은 Play Console에서 정합니다.
- OXXO 현금 결제처럼 돈이 나중에 들어오는 결제는 "결제 대기 중"으로 보이고, 결제가 끝나면 앱 복귀 때 자동으로 열립니다.
- Play가 보유하지 않았다고 확실히 답한 친구(구매 전이거나 환불)를 쓰고 있으면 랫서팬더로 돌아갑니다. 오프라인이거나 Play가 답하지 않으면 아무것도 빼앗지 않습니다.
- Play 상품 하나는 가격이 고정이라, 친구 하나를 이미 산 사람에게도 묶음은 같은 가격입니다. 묶음 시트에서 이미 가진 항목에 "보유"를 표시합니다.
- 테스트에서는 `FocusFriendApp`에 `purchases`를 넘기지 않으면 모든 친구가 열리고 판매 화면이 나오지 않습니다. 판매 화면 캡처: `flutter test tool/capture_purchases_test.dart`.
- 상품 ID는 Play Console에서 한 번 만들면 바꾸거나 다시 쓸 수 없습니다.
